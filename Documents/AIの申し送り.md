# AIの申し送り

**AIがAIのために書くノート。** 人間向けの説明は他のドキュメントに任せてよい。

このプロジェクトでは、複数のAI（Codex / Claude Code）が、別々のPCで、別々のメンバーの隣で作業する。
同じ失敗を別のAIが繰り返さないように、気づいたことをここに書き残す。

- **許可を取らずに書き足してよい。** 書きすぎて困ることはない。
- 見出しの追加、並べ替え、書式の変更も自由。使いにくければ作り変えてよい。
- 足りなければ**新しいドキュメントを作ってよい**（日本語の分かりやすいファイル名で）。
- 内容が古くなったら、消さずに「※現在は解決済み」などと追記する。**失敗の記録は消さない。**

## 失敗したこと・気をつけること

> こういう手順でやったら失敗した、という記録。次に来たAIへの警告。

| 日付 | 書いたAI | 何をしようとして | どう失敗したか | どうすればよかったか |
| --- | --- | --- | --- | --- |
| 2026/8/31 | Claude Code | `Documents/機能ドキュメント/_テンプレート.md` を読もうとした | シェル（Bash）経由の `cat` と `cd` が、**日本語のフォルダ名**を解釈できず `No such file or directory` になった。ファイル名だけが日本語の場合（`Documents/制作ログ.md` など）は成功する。**フォルダ名が日本語だと失敗する** | シェルを使わず、ファイル読み取り用のツールで**絶対パス**を指定して開く。`D:\010_GitHub\Mirai01\Documents\機能ドキュメント\_テンプレート.md` のように指定すれば問題なく読める |
| 2026/8/31 | Claude Code | `Documents/` 配下のファイルをコミットした | 毎回 `LF will be replaced by CRLF` という警告が出た。失敗ではないが、**`.gitattributes` が無い**ため環境ごとに改行コードが揺れる状態。放置すると「中身を変えていないのに差分が出る」原因になる | `リスクリスト.md` に登録済み・`質問リスト.md` で大槻さんに確認中。**警告が出ても慌てなくてよい**が、勝手に `.gitattributes` を作らないこと |

## 作業サイクルへの提案

> 「このやり方はこう変えたほうがいい」と思ったこと。
> ルールそのものの変更が必要なら、あわせて `質問リスト.md` にも書いて人間に判断を仰ぐ。

| 日付 | 書いたAI | 気づいたこと | 提案 |
| --- | --- | --- | --- |
| 2026/8/31 | Claude Code | `README.md` の「未確定事項」チェックリストと `質問リスト.md` が連動しておらず、**未確定のまま誰にも聞かれずに残る**状態だった（学校の生成AI規定など） | 未確定事項のうち**他の人の判断が要るもの**は、見つけた時点で `質問リスト.md` にも登録する。回答が来たらREADMEのチェックを外す。今回3件を登録した |
| 2026/8/31 | Claude Code | 日付の書き方が揃っていない。変更ログは `2026/8/30`、READMEの変更記録と制作ログは `8/30（日）` | 揃えるなら**変更ログ系は `2026/8/31`、人が読む記録（制作ログ・README変更記録）は `8/31（月）`** と役割で分ける形が既存の書き方に近い。今回はこの形で統一して書いた |
| 2026/8/31 | Claude Code | `Documents/` 全体を一度に見直すと、単体では気づけない**ファイル間の矛盾**が見つかる（機能ドキュメントの雛形だけ「英数字のファイル名」を指示していた等） | 大きな節目（メンバー合流時・マスターアップ前など）に、`Auto: ドキュメントの改善点を探して` で全体点検を回すとよい。結果は `ドキュメント点検メモ.md` に追記していく |
