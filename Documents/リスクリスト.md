# リスクリスト

「動くことを優先した結果、あとで問題になりそうな箇所」を書き残しておく場所。

バグが出たとき、**まずこのファイルを見れば原因の見当がつく**状態を目指す。
恥ずかしい実装を隠さず書くことが、後の自分たちを助ける。

## 書き方のルール

- 動作優先で安全性に不安が残る実装をしたら、その場でここに追加する。
- 複数ファイルにまたがるバグで原因が分からないときは、**まずこの表を上から確認する**。
- 直したら**行を消さず**に、対応状況を変えて「どう直したか」を書く。同じ罠を二度踏まないため。
- **対応状況**に書く言葉は次の4つから選ぶ。

  | 書く言葉 | 意味 |
  | --- | --- |
  | `未対応` | 見つけただけ。まだ手を付けていない |
  | `対応中` | 今まさに誰かが直している |
  | `対応済み` | 直した。**どう直したかを続けて書く**（例：`対応済み：読み込み前に中身を確認するようにした`） |
  | `様子見` | 直さないと決めた。**その理由を続けて書く**（例：`様子見：展示では起きない条件のため`） |

## リスク度の目安

| リスク度 | 意味 |
| --- | --- |
| **高** | 展示中に落ちる・進行不能になる可能性がある。マスターアップ前に必ず対応する |
| **中** | 特定の操作や条件で不具合が出る。時間があれば対応する |
| **低** | 今は問題ないが、機能を増やすと壊れるかもしれない。覚えておく程度 |
