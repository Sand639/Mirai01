## なにを考えているか

宇宙ごみ集めがある程度の形になったので、**別のリポジトリに分けて作りたい**という話（2026/9/24・大槻さん）。
やり方は**まだ決めていない**。決まったらこのファイルを更新すること。

## 決まっていること

- **共用しているフックの操作の部品は、新しいリポジトリで自由に直してよい**（2026/9/24・大槻さん）。
  つまり移行したら、**釣り側とは別物になる。** 小野田さんが釣りの操作感を直しても、宇宙ごみには入ってこない。

## 調べたこと（2026/9/24 時点）

### 宇宙ごみだけでは動かない

宇宙ごみ専用のファイルは79個あるが、動かすには**釣り側の部品が必要**。

| 使っているもの | 何に使うか |
| --- | --- |
| `HookController` / `ThrowController` / `HookProjectile` / `HookLine` / `HookChargeUI` / `HookAimAssist` | フックの操作そのもの |
| `HookableObject` / `FishingNetSupply` | 引っ掛けられる物と、その通信 |
| `FishingNetPlayer` / `FishingPlayerController` / `PlayerAimController` / `TopDownCameraFollow` / `PlayerStun` | プレイヤーの体・移動・狙い・カメラ |
| `FishingSceneBuilder` / `FishingObjectSpawner` / `FishingMatch` / `FishingTeams` | シーンを作るツールと、釣りのルールの一部 |
| `Scripts/Common/` `Scripts/UI/`（`GamePause` `PauseMenu` `GamepadInput` `DraggableGuiPanel` など） | ポーズ・入力・画面の共通部品 |

**「宇宙ごみのフォルダだけコピー」では動かない。**

### 移行のしかたの候補

| やり方 | よいところ | 気をつけること |
| --- | --- | --- |
| **リポジトリを丸ごと複製して、新しいほうで要らないものを削る**（おすすめ） | `.meta` の GUID がそのまま残るので**シーンとプレハブの参照が壊れない**。Unityの設定（入力方式・パッケージ・レイヤー・ビルドの一覧・Unityのバージョン）ごと移せる。履歴と経緯も残る | 最初は釣りやロボットも入ったままになる。削除は**Unity上で**行う（OSで消すと `.meta` が壊れる） |
| 空のプロジェクトに、必要なものだけコピー | 最初からきれいになる | **参照が切れやすい**。`.meta` ごと運ぶ必要があり、設定も手で入れ直す。確認の手間が大きい |

### 移行するなら必要なもの（チェックリスト）

- Unity のバージョン **6000.3.14f1**（変えない）
- パッケージ … `com.unity.netcode.gameobjects` `com.unity.services.multiplayer` `com.unity.inputsystem` `com.unity.multiplayer.center`
- `ProjectSettings`（**入力は新 Input System のみ**の設定・レイヤー・タグ・ビルドのシーン一覧）
- `Assets/InputSystem_Actions`（フックの操作・RT の割り当てがここ）
- `Documents/` … `README.md` `AGENTS.md` `CLAUDE.md`（AIへのルール）と、宇宙ごみ関連のドキュメント
- 仮素材 … `Assets/Art/Sprites/`（照準マーク・レーダー）と `共有フォルダ` の元データ

### あとで決めること

- 旧リポジトリの宇宙ごみを**残すか消すか**（残すと、どちらが最新か分からなくなりやすい）
- リポジトリの持ち主・メンバーの招待（GitHubのアカウント操作なので大槻さんが行う）
- 移行後、釣り側に戻したい修正が出たときの運び方
