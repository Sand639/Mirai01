## この機能は何か

**同じネットワークにつながっている複数のPCで、同じ空間に集まって遊べるようにする土台。**

1台を「ホスト（親）」にして、残りのPCがそこへ参加する形。
参加した人はそれぞれ自分のキャラクターを動かし、**その動きが他のPCの画面にも映る。**

**インターネットは使わない。** ハブとLANケーブルでつながっていれば動く。
展示会場のネットワークが不調でも遊べるようにするための作りである。

> **これはまだ「配線」だけで、ゲームの中身は入っていない。**
> ジャンルが決まっていなくても必要になる部分を、先に作ってある。

---

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| **W / A / S / D**（またはコントローラーの左スティック） | 自分のキャラクターが動く |
| 画面左上の**「ホストで開始」** | このPCが親になり、他のPCを待ち受ける |
| 画面左上の**「参加する」** | 入力したIPの親につなぎに行く |
| 画面左上の**「切断する」** | つながりを切って、最初の画面に戻る |

- 参加した順に**色が変わる**（青 → 赤 → 緑 → 黄）
- 出てくる場所も参加順にずれるので、**重なって出てこない**
- 画面左上に、**つながっている人数**と**自分の番号**が出る

## すぐ試す方法

### A. 1台のPCで2人分ためす（一番手軽）

**エディタの再生ボタンだけでは1人分しか動かない。**
通信は「2つ以上のゲームが同時に動いている」必要があるため、`.exe` を作って2つ起動する。

1. Unityのメニュー **`Tools > Mirai01 > LAN検証用のビルドを作る`** を実行する
   （数分かかる。終わるとフォルダが自動で開く）
2. 開いたフォルダの **`2人で自動接続.bat`** をダブルクリックする

これだけで**窓が2つ立ち上がり、そのままつながった状態**になる。
両方の画面にカプセルが2つ出れば成功。片方でWASDを押すと、もう片方の画面でも動く。

> 出力先は `Mirai01/Build/LanTest/`。**Gitには入らない**ので、コミットに混ざる心配はない。

#### ボタンを押す手順も試したいとき

同じフォルダの **`2つ起動するだけ.bat`** を使う。窓が2つ出るので、

1. 1つ目で **「ホストで開始」** を押す
2. 2つ目で、IPが `127.0.0.1` になっているのを確かめて **「参加する」** を押す

> `127.0.0.1` は「このPC自身」を指す決まった番号。同じPCの中だけで試すときに使う。

> **`.bat` は何をしているか**
> `.exe` を2つ起動しているだけ。あわせて**全画面ではなく小さめの窓で開く**よう指定している
> （そのまま起動すると全画面になり、2つ並べて見られないため）。

### B. 別のPCとつなぐ（本番の形）

#### 用意するもの

| 物 | 数 | 補足 |
| --- | --- | --- |
| **スイッチングハブ** | 1台 | **5ポート以上**のものを選ぶ。数千円で買える。「ハブ」「スイッチングハブ」で売っている |
| **LANケーブル** | PCの台数分 | 1〜3mあれば足りる。**カテゴリ5e以上**なら何でもよい |
| 電源タップ | 1つ | ハブの電源が要る |

> **インターネットにつながっている必要は無い。** ハブに挿さっているPC同士が話せればよい。
> **Wi-Fiでもつながることはある**が、学校や会場のWi-Fiは
> **PC同士の通信を禁止している場合がある**ので、**有線を推奨する。**

#### 手順1：物理的につなぐ

```
   PC1（親）─┐
   PC2 ─────┤
   PC3 ─────┼── スイッチングハブ ── 電源
   PC4 ─────┘
```

全部のPCのLAN差込口とハブを、LANケーブルでつなぐだけ。
**ハブのどのポートに挿しても構わない**（ルーターと違い、区別が無い）。

#### 手順2：IPアドレスを手で決める（重要）

**ハブだけの環境には、IPアドレスを配る役がいない。**
放っておくとWindowsが仮のアドレスを勝手に付けるが、**毎回変わる**ので当日困る。
そこで**手で固定してしまう。**

Windows 11での設定：

1. **設定 > ネットワークとインターネット > イーサネット**
2. **「IP 割り当て」**の横の **「編集」**
3. **「手動」**に切り替え、**「IPv4」をオン**
4. 次のように入れる（**PCごとに最後の数字だけ変える**）

| PC | IPアドレス | サブネットマスク | ゲートウェイ・DNS |
| --- | --- | --- | --- |
| **PC1（親）** | `192.168.10.1` | `255.255.255.0` | **空欄でよい** |
| PC2 | `192.168.10.2` | `255.255.255.0` | 空欄でよい |
| PC3 | `192.168.10.3` | `255.255.255.0` | 空欄でよい |
| PC4 | `192.168.10.4` | `255.255.255.0` | 空欄でよい |

5. **保存**

> **この設定をするとインターネットにつながらなくなる。**
> 展示のときはそれで構わないが、**普段使いのPCなら、終わったら「自動 (DHCP)」に戻すこと。**

#### 手順3：つながっているか確かめる（ゲームを起動する前に）

**先にここで確かめておくと、あとの切り分けが楽になる。**

PC2でコマンドプロンプトを開き、次を打つ。

```bash
ping 192.168.10.1
```

「応答がありました」と出れば、**ネットワークは正常**。
出なければ、**ケーブル・ハブの電源・IPの設定**のどれかが間違っている。ゲームを起動しても無駄なので先に直す。

#### 手順4：ゲームをつなぐ

1. **PC1（親）**で `LanPlayTest.exe` を起動し、**「ホストで開始」** を押す
2. **PC2〜4**で `LanPlayTest.exe` を起動し、**`192.168.10.1`** を入力して **「参加する」**

**最初の起動時に、Windowsのファイアウォールの確認画面が出る。**
**「プライベートネットワーク」にチェックを入れて「アクセスを許可する」** を押すこと。
ここで「キャンセル」を押すと、以後つながらなくなる。

> **1台ずつ増やす。** いきなり4台つなぐと、どこが悪いか分からなくなる。
> まず2台でつながることを確かめてから、3台目・4台目を足す。

#### つながらないときは、ここを見る

| 症状 | 原因として多いもの |
| --- | --- |
| `ping` が通らない | **ネットワークの問題。**ケーブルの挿し忘れ、ハブの電源、IPの入れ間違い。ゲーム以前の話 |
| `ping` は通るのに参加できない | **ファイアウォール。**初回の確認画面で許可しなかった可能性が高い。`Windows セキュリティ > ファイアウォールとネットワーク保護 > アプリケーションの許可` から `LanPlayTest` を探して、**プライベート**にチェックを入れる |
| そもそもIPが違う | `127.0.0.1` のままだと**自分自身につなぎに行く**。親のIPに書き換える |
| IPが複数出ている | 有線とWi-Fiの両方がつながっている。**検証中はWi-Fiを切る**と分かりやすい |
| つながるがすぐ切れる | ポート番号が違っていないか確認する（全PCとも `7777`） |

**ログにも記録が残る。** `[LAN]` で始まる行を見れば、どこまで進んで失敗したかが分かる。

## 展示当日の使い方（起動しただけでつながる）

毎回ボタンを押して回るのは手間なので、**ショートカットに引数を書いておく**と、
起動しただけで自動的につながる。

ショートカットを右クリック →「プロパティ」→「リンク先」の末尾に足す。

| PC | リンク先の末尾に足すもの |
| --- | --- |
| 親のPC | `-host` |
| 参加するPC（3台） | `-client 192.168.10.1` ← 親のIPに置き換える |

ポートを変えたいときは、続けて `-port 7777` のように書く。

> **親のIPは、上の「手順2」で固定しておくこと。** 毎回変わると、当日ショートカットを書き直すはめになる。

## 設定できる値（インスペクターの項目）

シーンの `NetworkManager` を選ぶと出てくる。

### Lan Connection Ui

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| **Address** | 参加するときの、つなぎ先のIP | 127.0.0.1 |
| **Port** | 使うポート番号。**全PCで同じ値にすること** | 7777 |
| Ui Scale | 画面表示の大きさ。**展示の大きい画面では上げる** | 1.5 |
| Show Ui | OFFにすると何も表示しない（本番の画面ができたら切る） | ON |

### Lan Auto Start

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Auto Host In Editor | ONにすると、エディタでの再生時に自動でホストになる | OFF |

### Network Player（プレハブ側）

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Move Speed | 進む速さ（1秒あたりのメートル） | 5 |
| Turn Speed | 進む方向へ向き直る速さ | 720 |
| Gravity | 落ちる強さ。**マイナスの値にすること** | -20 |
| **Player Colors** | 参加順に割り当てる色。**4色入っている** | 青／赤／緑／黄 |
| Spawn Radius | 中心からどれだけ離れた場所に出てくるか（m） | 3 |

## 仕組み（分かる人向け）

- 通信は **Netcode for GameObjects**（Unity公式）を使っている
- **ホスト方式**。1台が「サーバー兼プレイヤー」を兼ねる。専用サーバーは要らない
- 位置合わせは **`NetworkTransform` の Owner 権限**。
  **動かしている本人が位置を送り、他のPCはそれを再現する**形にしている
- 自分以外のキャラクターは、`CharacterController` を切ってある。
  切らないと、送られてきた位置へ移そうとしても押し戻してしまうため
- **色は通信で送っていない。** 参加番号から計算しているので、どのPCで見ても同じになる
- 接続部品（`UnityTransport`）のIPとポートだけを差し替える作りなので、
  **将来インターネット対応（Unity Relay）を足すときも、ゲーム側は書き換えずに済む**

### なぜ Netcode for GameObjects を選んだか

| 候補 | 判断 |
| --- | --- |
| **Netcode for GameObjects** | **採用。**Unity公式・無料で、**インターネット無しのLANだけで動く** |
| Mirror | 次点。LANで動くが、公式ではない |
| PUN 2 | **不採用。**クラウド経由のため**インターネットが必要**。メーカー自身も新規はFusionを推奨している |
| Photon Fusion | 不採用。同じくクラウド前提 |

**決め手は「当日インターネットが無くても遊べること」。**
展示会場のネットワークは自分たちで制御できないため。

## できていないこと・既知の問題

- **別PC同士での確認をしていない。**
  同じPCの中で2つ起動してつながることは**実際に確認済み**（ログで2人分の生成を確認）。
  ただし**LANケーブルで別のPCとつなぐ確認は、私（AI）にはできない**ので未実施
- ~~4人同時は未確認~~ → **2026/9/3に、1台のPCで4つ起動して確認済み。**
  4色とも出て、番号も 0〜3 まで正しく割り当てられた（大槻さんが確認）
- **画面が仮のもの。** 接続の画面は簡易表示で作ってある。**本番のタイトル画面はあとで作り直す前提**
- **視点が回せない。** カメラは後ろから追いかけるだけで、マウスや右スティックでは回らない
- **ズルへの対策が無い。** 位置を本人が申告する形なので、**改造すれば壁抜けなどができてしまう**。
  展示のように**閉じたLANで、目の前の4人だけで遊ぶ**分には問題にならないと判断している
- **音・演出・名前表示が無い。** 誰が誰かは色だけで見分ける
- **切断したあとの再接続を試していない。** 途中で抜けた人がもう一度入れるかは未確認
