## この機能は何か

**釣り竿のようなフックで、フィールドに落ちている「物資」を引っ掛けて、引き寄せて、勢いよく投げる**遊びの土台。
「Last Shark Standing」のようなフック・投擲アクションを参考にしている。

見下ろしに近い視点の3D。プレイヤーはいつもマウスカーソルの方を向く。
左クリックを押し込んでいる時間でフックの飛距離が決まり、離すと発射する。
物資に当たると引き寄せが始まり、動くゲージが「当たり」の枠に入った瞬間に左クリックすると、強く投げられる。

見た目より**操作感と基本の流れ**を優先した、調整前のプロトタイプ。

---

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| WASD | 地面を移動する |
| マウスを動かす | プレイヤーがカーソルの方向を向く（この向きが「前」） |
| 左クリックを押す | フックを構える。押している間、下のバーがたまっていく（チャージ） |
| 左クリックを離す | カーソル方向へフックが飛ぶ。飛距離はチャージ量で決まる（最大値あり） |
| フックが物資に当たる | 物資がフックされ、プレイヤーの方へ引き寄せられ始める。タイミングのゲージが左右に動き出す |
| 引き寄せ中に左クリック | その瞬間のゲージ位置で投げの強さが決まり、物資が飛ぶ |
| フックが何にも当たらない | 最大距離まで伸びて、手元へ戻る |

投げの強さ（仕様どおり3段階）

| ゲージの位置 | 強さ |
| --- | --- |
| 枠の外 | 通常（普通の力で投げる） |
| 黄色い枠の中 | 強い力 |
| 緑の枠の中（ほぼ中心） | 非常に強い力 |

投げる方向は、いまは**プレイヤーの後方**（フックを撃った向きの反対）が初期設定。
Inspector で「前方」「カーソル方向」「固定方向」にも変えられる。

## 検証シーンの作り方・確かめ方

1. Unityで、いったんスクリプトのコンパイルが通るのを待つ（Consoleに赤エラーが無いこと）。
2. メニュー **`Tools > Mirai01 > 釣りフックの検証シーンを作る`** を実行する。
3. `Assets/Scenes/Test/FishingHookTest.unity` が開く（自動で開かなければダブルクリックで開く）。
4. 再生ボタンを押す。WASDで動き、マウスで向きを変え、左クリックでフックを試す。

このシーンは**検証用なので、ビルド（`File > Build Settings` のシーン一覧）には入れない**こと。

## 設定できる値（インスペクターの項目）

すべてプレイヤー（`PlayerRig`）に付いた各スクリプトから調整できる。

### HookController（フックの発射）

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Charge Time | 押しっぱなしでチャージ最大になるまでの秒数 | 1.0 |
| Min Range / Max Range | チャージ0とチャージ最大のときの飛距離（m）。Max が飛距離の最大値 | 4 / 16 |
| Fly Speed / Return Speed | フックが伸びる速さ／戻る速さ（m/s） | 30 / 45 |
| Hook Cast Radius | 当たりを見る球の半径。大きいほど引っ掛けやすい | 0.35 |

### ThrowController（引き寄せと投げ）

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Reel Speed | 物資をプレイヤーへ引き寄せる速さ（m/s） | 7 |
| Hold Distance | この距離まで近づくと引き寄せを止めて手元に留める（m） | 2 |
| Timing Cycle | ゲージが端から端まで動く秒数。短いほど難しい | 1.1 |
| Target Center | ゲージ上の「当たり」の中心（0〜1） | 0.75 |
| Good Window / Perfect Window | 「強い力」「非常に強い力」になる範囲（中心からの片側の広さ、0〜1） | 0.16 / 0.05 |
| Throw Force Normal / Good / Perfect | 各段階の投げる力 | 8 / 14 / 22 |
| Throw Lift | 投げるときに少し上向きに加える力（0で真横） | 2 |
| Direction Mode | 投げる方向（Backward／Forward／AimAtCursor／WorldCustom） | Backward |
| Custom Direction | Direction Mode が WorldCustom のときの固定方向 | (0,0,0) |

## 仕組み（分かる人向け）

- **狙点の共有**：`PlayerAimController` がカメラからマウスへレイを飛ばし、地面との交点を `AimPoint`、
  そこへの水平な向きを `AimDirection`（＝「前方向」）として公開する。移動の向き・フックの発射・投げの方向は、
  すべてここを読む。方向の定義を1か所にまとめてあるので、仕様6・7の「方向の追加・変更」がしやすい。
- **状態管理**：`HookController` が `Idle / Charging / Flying / Returning / Attached` の5段階を持つ。
  フックの飛び方（等速で前進、`SphereCast` で当たり確認、最大距離で折り返し）はここで計算し、
  `HookProjectile` は「物資に触れた」ことを報告するだけの薄い部品にしている。
- **引き寄せと投げ**：物資に当たると `HookController` が `ThrowController.Begin()` を呼ぶ。
  `ThrowController` は物資の Rigidbody の速度を毎 FixedUpdate でプレイヤー方向へ向け、
  近づいたら止める。左クリックの瞬間のゲージ位置で段階（Normal/Good/Perfect）を判定し、
  `AddForce(方向 × 力 + 上向き, Impulse)` で飛ばす。方向は `ResolveDirection(mode, tier)` に集約。
  `tier`（タイミングの良さ）は今は方向に影響しないが、仕様7「タイミングで方向を変える」を足すときに
  ここで分岐できるよう、引数だけ先に受け取ってある。
- **既存 PlayerRig の扱い**：体の見た目は `PlayerRig.prefab` を複製して使うが、
  中に入っている一人称/三人称のマウス視点操作（`PlayerController` / `PlayerViewSwitcher`）と内蔵カメラは
  見下ろしと噛み合わないので、生成ツールが**無効化・除去**している。`PlayerRig.prefab` 本体は変更していない。

## できていないこと・既知の問題

- **見た目は仮**。プレイヤー・フック・物資・糸はすべて Unity の基本形状で、調整前。
- フックが壁に当たっても止まらず、すり抜けて戻る（プロトタイプのため未対応）。
- 引き寄せ中の物資は重力を切っているため、床にめり込む地形では不自然に見える可能性がある。
- タイミング判定・力・距離の数値は**未調整**。操作感を見ながら Inspector で詰める前提。
- `Assets/Scripts/Fishing/` フォルダを新規作成した（既存の機能別フォルダの並びに合わせたが、
  フォルダ新規作成は事前確認の決まりのため `質問リスト.md` に事後登録済み）。
